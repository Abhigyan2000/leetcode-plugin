# Security

Do not include LeetCode cookies, tokens, or private submission data in GitHub issues or pull requests. Report sensitive issues privately using GitHub private vulnerability reporting if enabled on this repository. If that channel is unavailable, open an issue requesting a private contact without including exploit details or secrets.

Credentials confer account access. Store them only in your own local application data or process environment. This version stores local credentials in plaintext, with POSIX owner-only modes and Windows inherited user-profile permissions; it does not implement an OS keychain. Never use a shared account cookie to serve multiple users.

The local MCP server uses stdio. Optional local setup temporarily listens on a random port on `127.0.0.1`, with a random setup path, exact Host and Origin checks, no cross-origin access, bounded form requests, no external page assets, and no-store responses. It closes after success, cancellation, or the five-minute deadline. The user explicitly copies session values into that local page; they never enter MCP tool arguments or chat. Do not expose this listener on a network interface. API requests go to the fixed LeetCode origin and do not follow redirects. It does not execute submitted code locally. Non-idempotent operations are not retried automatically. Tool annotations distinguish account writes from read operations, and the bundled skill requires the user's authorization for submission.

Browser sign-in launches a separate, temporary browser profile, following Chrome's requirement that remote debugging use a non-default data directory. The debugging port binds to loopback and is closed after sign-in; as with other local debugging ports, another process running on your machine could access it while open. Only use sign-in on a computer you trust. The plugin must never be pointed at an existing browser profile. The browser executable override accepts an absolute executable path, not a shell command.

Default-browser discovery reads system associations and never changes them. The registered browser command is not executed as a shell string. Unsupported defaults produce an error instead of silently selecting another installed browser. On Windows, cleanup also closes any remaining browser processes whose `--user-data-dir` exactly matches the temporary profile, including Edge processes started through a launcher handoff. Normal browser profiles are not targeted.

The sign-in adapter requests only LeetCode cookies from LeetCode page targets. It does not read identity-provider cookies, password fields, page contents, or network request bodies. The profile is removed after normal completion, cancellation, or timeout; a crash can leave a profile behind. Login status reports cleanup failures. Credentials are saved only after LeetCode verifies the session. A failed login does not replace saved credentials. Website challenges and any identity-provider restrictions are handled by the user through the site's normal interface.

Website APIs can change. Respect LeetCode's access controls, terms, premium requirements, and rate limits. If a request encounters a browser challenge, sign in using the normal website; this plugin does not solve or bypass challenges.
